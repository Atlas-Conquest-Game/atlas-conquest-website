# Data Model

> Defines the JSON data contracts between the pipeline (`scripts/`) and the frontend (`site/`).

## Data Files

All files live in `site/data/` and are generated by `scripts/pipeline/` (entry point: `scripts/fetch_data.py`).

| File | Description | Time-filtered |
|------|-------------|:---:|
| `metadata.json` | Match counts, player counts, timestamps | Yes |
| `commander_stats.json` | Per-commander winrate, matches, wins | Yes |
| `matchups.json` | Commander-vs-commander winrate matrix | Yes |
| `card_stats.json` | Per-card play/draw/deck rates and winrates | Yes |
| `commander_card_stats.json` | Per-commander card inclusion, winrates, copies (lazy-loaded) | Yes |
| `trends.json` | Weekly faction popularity percentages | Yes |
| `commander_trends.json` | Weekly per-commander popularity percentages | Yes |
| `commander_winrate_trends.json` | Weekly per-commander winrate (with/without mirrors) | Yes |
| `game_distributions.json` | Duration, turns, actions histograms | Yes |
| `deck_composition.json` | Per-commander deck cost, type ratios, loyalty | Yes |
| `duration_winrates.json` | Per-commander winrate by game duration buckets | Yes |
| `action_winrates.json` | Per-commander winrate by action-count buckets | Yes |
| `turn_winrates.json` | Per-commander winrate by turn-count buckets | Yes |
| `first_turn.json` | First-turn advantage stats, overall and per-commander | Yes |
| `mulligan_stats.json` | Per-card mulligan keep rate, keep/return winrates | Yes |
| `commander_mulligan_stats.json` | Per-commander card mulligan stats (lazy-loaded) | Yes |
| `feedback_stats.json` | Per-card post-match feedback (fun / not fun) ratios, global and per-commander (lazy-loaded) | Yes |
| `cards.json` | Card definitions from CSV, tokens included (reference data) | No |
| `commanders.json` | Commander definitions from CSV (reference data) | No |
| `mentions.json` | Card slug → cards it creates/references (reference data) | No |
| `goals.json` | Alpha art/animation goals, art-source and patron breakdowns | No |
| `insights/*.json` | Derived layer for analytics v2 (built by `scripts/build_insights.py` from the files above) — see [Insights layer](#insights-layer-sitedatainsights) | Own nesting |

## Time Period Nesting

Stats files are doubly nested by time period and map. The frontend reads `data[period][map]` where period is one of `all`, `6m`, `3m`, `1m` and map is one of `all`, `Dunes`, `Snowmelt`, `Tropics`.

```json
{
  "all": {
    "all": <full data>,
    "Dunes": <dunes only>,
    "Snowmelt": <snowmelt only>,
    "Tropics": <tropics only>
  },
  "6m": { "all": ..., "Dunes": ..., ... },
  "3m": { ... },
  "1m": { ... }
}
```

Reference files (`cards.json`, `commanders.json`) are flat arrays — no period/map nesting.

## Schema Definitions

### metadata.json
```json
{
  "all": {
    "all": {
      "last_updated": "2026-10-05T14:12:44.907788+00:00",
      "total_matches": 5229,
      "total_players": 240,
      "data_version": "3.1.0"
    },
    "Dunes": { ... }
  },
  "6m": { ... },
  "3m": { ... },
  "1m": { ... }
}
```

`data_version` history: `3.0.0` — weekly keys from `strftime("%Y-W%W")`;
`3.1.0` — weekly keys are ISO-8601 weeks and `commander_stats` rows carry
`pilots`. `scripts/insights/weeks.py` reads this value to parse week keys, so
bump it (`DATA_VERSION` in `scripts/pipeline/constants.py`) whenever the week
scheme changes.

### commander_stats.json
```json
{
  "all": {
    "all": [
      {
        "name": "Jagris, the Huntsman",
        "faction": "grenalia",
        "matches": 983,
        "wins": 590,
        "winrate": 0.6002,
        "pilots": 72
      }
    ],
    "Dunes": [ ... ]
  },
  "6m": { ... },
  "3m": { ... },
  "1m": { ... }
}
```

Rows are sorted by `matches` (player-games; a mirror game counts twice, once
per seat). `pilots` (added in data_version 3.1.0) is the number of distinct
player names that played the commander in that period × map (blank names and
the "Unknown" default are not counted). Read it as:

| Row | Meaning |
|---|---|
| `"pilots": 12` | 12 distinct players |
| `"pilots": null` | fewer than 5 players (`MIN_PILOTS_PUBLISHED`) |
| no `pilots` key | file predates 3.1.0 — unknown |

In JS: `!('pilots' in row)` → unknown; `row.pilots === null` → fewer than 5.

### card_stats.json
```json
{
  "all": {
    "all": [
      {
        "name": "Fireball",
        "faction": "neutral",
        "type": "Spell",
        "token": false,
        "deck_count": 1200,
        "deck_rate": 0.1932,
        "deck_winrate": 0.5100,
        "drawn_count": 800,
        "drawn_rate": 0.1288,
        "drawn_winrate": 0.5250,
        "played_count": 600,
        "played_rate": 0.0966,
        "played_winrate": 0.5400,
        "avg_copies": 2.64,
        "drawn_instances": 1450,
        "played_instances": 980
      }
    ]
  }
}
```

| Field | Type | Description |
|-------|------|-------------|
| `token` | bool | Generated card (from `StandardFormatTokens.csv`) — has real draw/play stats but no deck can contain one. The Cards page hides these unless "Show tokens" is checked. |
| `deck_count` | int | Number of decks containing this card |
| `deck_rate` | float | `deck_count / total_player_games` |
| `drawn_count` | int | Number of games where this card was drawn |
| `drawn_instances` | int | Total copies drawn (counts each copy separately) |
| `played_count` | int | Number of games where this card was played |
| `played_instances` | int | Total copies played (counts each copy separately) |
| `avg_copies` | float | `total_copies / deck_count` — average copies per deck that includes it |
| `cost` | int | Mana cost from the card CSV (`null` if unknown) |
| `not_drawn_count` / `not_drawn_winrate` | int / float | Games where the card was in the deck but never drawn, and the winrate in them |
| `iwd` | float | Improvement when drawn: `drawn_winrate - not_drawn_winrate`. `null` if either side has no games |
| `play_when_drawn` | float | Games where the card was drawn *and* played / games where it was drawn |
| `wr_vs_expected` | float | `(played_wins - Σ pilot commander winrate) / played_count` — played WR net of commander strength. Commander winrates are from the same period × map |
| `first_played_count` / `first_played_winrate` | int / float | Played by the player going first (turn order from `first_player`, else mulligan inference; undetermined games excluded) |
| `second_played_count` / `second_played_winrate` | int / float | Same, going second |
| `played_avg_turns` | float | Average turns the player took in games where the card was played |
| `played_turns_delta` | float | `played_avg_turns` minus the average turns across all player-games in scope |

### commander_card_stats.json

Lazy-loaded on first commander selection. Nested `data[period][map][commander_name]` → array of card objects sorted by inclusion rate (all cards, no limit).

```json
{
  "all": {
    "all": {
      "Fael Spiritwalker": [
        {
          "name": "Killing Hex",
          "inclusion_rate": 0.9415,
          "drawn_rate": 0.7018,
          "drawn_winrate": 0.4833,
          "played_rate": 0.5789,
          "played_winrate": 0.4798,
          "drawn_count": 240,
          "played_count": 198,
          "drawn_instances": 424,
          "played_instances": 312,
          "avg_copies": 2.87,
          "deck_count": 322,
          "games": 342
        }
      ]
    }
  }
}
```

| Field | Type | Description |
|-------|------|-------------|
| `inclusion_rate` | float | `deck_count / games` for this commander |
| `games` | int | Total games played with this commander (denominator for all rates) |
| `deck_count` | int | Number of this commander's decks containing the card |
| `avg_copies` | float | Average copies in decks that include it |
| `deck_winrate` | float | Winrate of this commander's decks that include the card |
| Advanced fields | | `not_drawn_*`, `iwd`, `play_when_drawn`, `wr_vs_expected`, `first_played_*`, `second_played_*`, `played_avg_turns`, `played_turns_delta` — as in `card_stats.json`, scoped to this commander. `wr_vs_expected` is played WR minus the commander's own winrate; `played_turns_delta` compares to the commander's average game. |

Written compact (no indentation) — the file is several MB.

### Week keys (trends.json, commander_trends.json, commander_winrate_trends.json)

`dates` are `YYYY-Www` keys, sorted chronologically. From data_version 3.1.0
they are ISO-8601 weeks (`isocalendar()`: Monday–Sunday, ISO week-numbering
year — 2025-12-29 … 2026-01-04 is `2026-W01`). Earlier files used
`strftime("%Y-W%W")`, which numbers most years one lower than ISO and splits
the New Year week into `YYYY-W52` + `YYYY+1-W00`. Weeks with fewer than 4
games (picks for `trends`/`commander_trends`) are omitted, so a missing week
means "almost no games", not "no data".

Frontend note: convert an ISO key to a date as "the Monday of the week that
contains January 4 of that year, plus 7·(week − 1) days". The legacy
`new Date(year, 0, 1 + 7·week)` approximation in `site/js/meta.js` happened to
fit `%W` keys; with ISO keys it lands a week late in years like 2026, so month
bins shift by a week. Update it before the 3.1.0 pipeline output ships (or
check `metadata.json` `data_version`).

### duration_winrates.json / action_winrates.json / turn_winrates.json

All three share the same structure — per-commander winrate broken into buckets.

```json
{
  "all": {
    "all": {
      "buckets": ["0-10", "10-20", "20-30", "30+"],
      "commanders": {
        "Jagris, the Huntsman": [
          { "winrate": 0.5714, "games": 98 },
          { "winrate": 0.5200, "games": 150 },
          { "winrate": 0.4800, "games": 75 },
          { "winrate": 0.4000, "games": 30 }
        ]
      }
    }
  }
}
```

Bucket labels differ per file:
- **duration**: `["0-10", "10-20", "20-30", "30+"]` (minutes)
- **actions**: `["0-30", "30-60", "60-90", "90-120", "120+"]`
- **turns**: `["1-5", "5-8", "8-11", "11-14", "14+"]`

Each commander has one `{ winrate, games }` entry per bucket. `winrate` is null when games = 0.

### cards.json (flat — no period nesting)
```json
[
  {
    "name": "Fireball",
    "type": "Spell",
    "text": "Deal 3 damage to a character.",
    "subtype": "",
    "cost": 3,
    "attack": null,
    "speed": null,
    "health": null,
    "legendary": false,
    "faction": "neutral",
    "art": "CardScreenshots/Fireball.png",
    "mentions": [],
    "token": false
  }
]
```

Built from `StandardFormatCards.csv` **plus** `StandardFormatTokens.csv`. Tokens
are generated cards (Zombie, Lucian Soldier, …): they carry `"token": true` and
are otherwise identical records, so anything that needs a card's type/faction
resolves them like any other card. Consumers that mean "buildable cards" — the
deck builder's card pool, the Goals art tracker — must filter `token` out.

`mentions` lists the cards this one creates or references, from the
`MentionedCards` CSV column. Names are raw CSV values; use `mentions.json` for
the resolved, slugged form.

### mentions.json (flat — no period nesting)
```json
{
  "conscription": [{ "name": "Lucian Soldier", "slug": "lucian-soldier" }],
  "elyse-of-the-order": [{ "name": "Lucian Soldier", "slug": "lucian-soldier" }]
}
```

Card (or commander) art slug → the cards it creates or references, resolved from
the `MentionedCards` column of the reference CSVs. Keyed by slug, not name, so a
caller holding only `data-card-slug` can look up directly; the slug is also the
`/assets/cards/<slug>.jpg` and `/assets/card-art-png/<slug>.png` filename.
Cards that mention nothing are omitted, and mentioned names that don't resolve
to a known card are dropped at build time.

`site/js/cardpreview.js` loads this on every page and renders the mentioned
cards beside the card itself — in the hover popup, in the Decks detail sheets,
and (server-rendered by `build_articles.py`) in articles.

### goals.json (flat — no period nesting)
```json
{
  "art_goals": [ { "id": "art_count", "label": "100 Cards with Human Art", "kind": "count",
                   "current": 78, "target": 100, "met": false } ],
  "animation_goals": [ "…same shape…" ],
  "overall": {
    "cards": {
      "total": 274,
      "human": 140,
      "human_rate": 0.5109,
      "animated": 70,
      "animated_rate": 0.2555,
      "art_types": {
        "commissioned": { "count": 76, "rate": 0.2774 },
        "purchased":    { "count": 2,  "rate": 0.0073 },
        "placeholder":  { "count": 62, "rate": 0.2263 },
        "ai":           { "count": 134, "rate": 0.4891 },
        "other":        { "count": 0,  "rate": 0.0 }
      }
    },
    "tokens": "…same shape…",
    "commanders": "…same shape…",
    "all": "…same shape — cards + tokens + commanders…"
  },
  "by_patron": [ { "patron": "Skaal", "faction": "skaal",
                   "cards": "…totals…", "commanders": "…totals…" } ]
}
```

`human` is human-made art of any kind — it equals `art_types.commissioned +
art_types.purchased + art_types.placeholder` — and it is what every goal
counts. `placeholder` is `COMMISSIONED_PLACEHOLDER` art: human-made, standing
in for a commission that is not finished, kept as its own bucket so the
in-progress share stays visible. The `art_types` buckets always sum to
`total`; `other` catches any `ArtType` the pipeline doesn't recognise
(normally zero, and the Goals page hides it when it is). The raw value →
bucket map lives in `scripts/pipeline/constants.py`. Card and commander
records in `cards.json` / `commanders.json` carry the same flag as
`human_art`.

**Tokens**: no alpha goal targets them, so they're excluded from every entry in
`art_goals` / `animation_goals` and from `by_patron`. They appear only as
`overall.tokens` and inside `overall.all`, which is the combined final count.

### mulligan_stats.json
```json
{
  "all": {
    "all": [
      {
        "name": "Throne Guardian",
        "kept_count": 26,
        "returned_count": 11,
        "total_seen": 37,
        "keep_rate": 0.7027,
        "norm_keep_delta": 0.2185,
        "keep_winrate": 0.5,
        "return_winrate": 0.5455,
        "winrate_delta": -0.0455,
        "mulligan_games": 154
      }
    ]
  }
}
```

| Field | Type | Description |
|-------|------|-------------|
| `kept_count` | int | Times this card was kept in opening hand (count-weighted for duplicates) |
| `returned_count` | int | Times this card was returned/mulliganed (count-weighted) |
| `total_seen` | int | `kept_count + returned_count` |
| `keep_rate` | float | `kept_count / total_seen` |
| `norm_keep_delta` | float | `keep_rate - expected_keep_rate`. Expected rate = cards_to_keep / intellect per hand, averaged across all appearances. Positive = actively preferred over random. `null` if no intellect data |
| `keep_winrate` | float | Winrate when card was kept. `null` if kept_count = 0 |
| `return_winrate` | float | Winrate when card was returned. `null` if returned_count = 0 |
| `winrate_delta` | float | `keep_winrate - return_winrate`. Positive = keeping correlates with winning. `null` if either is null |
| `mulligan_games` | int | Total player-games with mulligan data (context for sample size) |

### feedback_stats.json

Post-match "did you have fun?" answers (`feeling` = `fun` / `not_fun` on the game row's `feedback` blob, joined to players by seat `playerid`). Lazy-loaded by the Cards page. Written compact. Nested `data[period][map]` → object:

```json
{
  "3m": {
    "all": {
      "total_ratings": 412,
      "fun_rate": 0.71,
      "cards": [
        {
          "name": "Throne Guardian",
          "any_ratings": 58, "any_pos_rate": 0.7414, "any_neg_rate": 0.2586,
          "played_ratings": 30, "played_pos_rate": 0.8, "played_neg_rate": 0.2,
          "opp_ratings": 29, "opp_pos_rate": 0.6897, "opp_neg_rate": 0.3103
        }
      ],
      "by_commander": { "Fael Spiritwalker": [ { "name": "...", "...": "same row shape" } ] }
    }
  }
}
```

The unit is one player's answer for one game. For card C in a game with at least one answer:

| Scope | Which answers count |
|-------|---------------------|
| `any` | Every answer in the game, if either player played C |
| `played` | The answer of each player who played C |
| `opp` | The answer of each player whose opponent played C |

`by_commander[cmd]` restricts to games where a player on `cmd` played C: `played` = that player's answer, `opp` = their opponent's, `any` = all answers in the game. `*_pos_rate` + `*_neg_rate` = 1; both are `null` when that scope has no ratings. `total_ratings` / `fun_rate` are the baseline across all rated games in the period × map.

## Insights layer (`site/data/insights/`)

Derived files for the analytics v2 pages (State of the Meta hub, commander
profiles, "What beats X?", Cards Analyst view, Community Decks). Built by
`python scripts/build_insights.py` from the **published** `site/data/*.json`
(plus the git history of `site/data/cards.json` for the first changelog run).
It never reads the raw cache or AWS and never writes outside
`site/data/insights/` (plus the unpublished review file
`scripts/review/changelog_text.json`). CI runs it right after
`fetch_data.py`; a later frontend step (`generate_commander_pages`) will
consume `insights/commanders/<slug>.json`.

Ground rules (owner decisions):

- **No tier lists or tier labels.** Every rate is published with a 95%
  interval and its sample size; verdicts are plain language and only say what
  the interval supports.
- Usernames and deck names are kept (community decks, profile deck examples).
- All games are included (no test-account filtering).
- Deterministic: the only "now" is `as_of` (`--as-of`, default
  `metadata.json` `all.all.last_updated`). Re-running on the same inputs
  rewrites nothing. No NaN/Infinity anywhere (the writer refuses them).
- Code: `scripts/insights/` (`stats_kit`, `concentration`, `weeks`,
  `matchup_model`, `meta_pulse`, `card_changelog`, `profiles`,
  `community_decks`, `build`). Tests: `scripts/tests/test_insights.py`.
- Failure-safe: every file is computed before any is written, so a failed
  run leaves the previous insights untouched. In CI the step is
  `continue-on-error` (the daily data commit never waits on it) and failures
  show as `::error::` annotations. Exit codes: 0 ok, 1 error, 2 refused to
  start an empty card changelog (see card_changelog below).

### Insights: stats kit (mirror these rules in the frontend)

`scripts/insights/stats_kit.py`.

- **Interval:** 95% Wilson score interval, `wilson(w, n, z=1.96)`:
  `center = (p + z²/2n) / (1 + z²/n)`,
  `half = z·sqrt(p(1−p)/n + z²/4n²) / (1 + z²/n)`; `lo = 0` when `w = 0`,
  `hi = 1` when `w = n`.
- **Gates:** `MIN_GAMES_FOR_ESTIMATE = 20` — below this no point estimate
  (wr/lo/hi are `null`), only the count. `LOW_DATA_GAMES = 40` — below this
  the estimate carries `low_data: true`.
- **Verdict** `verdict(lo, hi, n)`, first match wins:

  | Condition | `verdict` | `verdict_label` |
  |---|---|---|
  | n < 20 | `too_early` | Too early to tell (no estimate shown) |
  | lo > 0.5 | `above_even` | Above even |
  | hi < 0.5 | `below_even` | Below even |
  | straddles 0.5, n < 40 | `too_early` | Too early to tell (estimate shown) |
  | straddles 0.5, n ≥ 40 | `even` | Even as far as we can tell |

- **Pilot gates** (`apply_pilot_gates`), applied after the n < 20 rule and
  before the interval rules wherever the sample's pilots are known. They exist
  because a sample that is mostly one person's games describes that person,
  and the Wilson interval (independent games) is far too narrow for it:

  | Condition | `verdict` | `verdict_label` |
  |---|---|---|
  | `commander_stats` `pilots` is `null` (key present: < 5 players) | `few_players` | Fewer than 5 players |
  | `concentration.top_pilot_share` > 0.5 | `one_player` | Mostly one player's games |

  Both keep `games`/`wins` and null `wr`/`lo`/`hi`.
- **Concentration** object (`scripts/insights/concentration.py`), attached to
  commander records and archetype rows:
  `{ "top_pilot_share": 0.5882, "pilots_listed": 10, "listed_share": 0.9748, "concentrated": true }`.
  The pipeline publishes no per-player counts, so this is an **estimate** from
  archetypes.json: every listed exact decklist's games are credited to its most
  common pilot, and the busiest pilot's credited games are divided by the
  sample's games. Lists outside the top 20 per archetype are unseen
  (`listed_share` = how much of the sample the lists cover) and other people's
  games on the same exact list are credited to its main pilot. "Unknown"
  usernames are never credited; alt accounts (e.g. "Michael"/"Michael1") count
  as different people. `top_pilot_share` is `null` when no named list covers
  the sample (then `concentrated` is false).
- **Rate block** — the standard record shape used everywhere below:

  ```json
  { "games": 150, "wins": 84, "wr": 0.56, "lo": 0.48, "hi": 0.637,
    "verdict": "even", "verdict_label": "Even as far as we can tell", "low_data": false }
  ```
  `wr`/`lo`/`hi` are `null` when `games < 20` or when a pilot gate applies.
  `verdict` is one of `above_even`, `below_even`, `even`, `too_early`,
  `one_player`, `few_players`; `gates.stats_kit.verdicts` in index.json maps
  them to labels.

```json
  } } }

```

- Source: ordered-pair records in `matchups.json`, **mirror matches excluded**.
- **Strengths are model inputs, not a ranking.** Bradley-Terry fit by Hunter's
  MM iteration; one virtual win and one virtual loss per commander against an
  average opponent keep undefeated/winless commanders finite; renormalised to
  geometric mean 1 (strength 1 = field average). `strength_lo`/`strength_hi`:
  95% interval from the observed Fisher information, for log-strength
  relative to the field mean (`log_strength_se`). `expected_vs_field =
  s/(s+1)` (expected winrate vs an average opponent) with the same interval.
  **All strength fields are `null` below 20 non-mirror games**
  (`games`/`wins` are always there). `commanders[]` is **alphabetical**. Do
  not render strengths as a sorted list or a ranking; to say how a commander
  does overall, show its mirror-free record (profile `record`, hub
  `commander_overview`).
- **Pairs:** both orientations of every **played** pair; a missing pair means
  no recorded games. `expected = s_a/(s_a+s_b)`, `null` when either side's
  strength is gated (the model still uses it internally). `est` = posterior
  mean of `Beta(20·expected + wins, 20·(1−expected) + losses)` (prior weight
  20 games centred on the strength expectation), `lo`/`hi` = 95%
  equal-tailed posterior interval. **`est`/`lo`/`hi`/`favored` are `null`
  below 10 games** — show the record (`wins`–`n − wins`) only. `est_ab = 1 −
  est_ba`, `lo_ab = 1 − hi_ba` exactly. `raw_wr` is `null` below 20 games.
- **`favored`** (`"a"`, `"b"` or `null`): set only when the posterior
  interval excludes 0.5 **and** the raw record points the same way. Never
  infer "favored" from `est` alone.
- **Evidence** (same for both orientations; labels in
  `method.evidence_labels` / `index.gates.matchup_model.evidence_labels`):

  | `evidence` | Rule | Label |
  |---|---|---|
  | `low-data` | n < 10 | Not enough games |
  | `counter` | n ≥ 20, `favored` set, the favored side beats the strength expectation (its interval bound clears `expected` by > 0.02) and \|est − 0.5\| ≥ 0.10 | Counter (beats what overall strength predicts) |
  | `lean` | `favored` set, not a counter | Leans one way |
  | `even` | interval straddles 0.5 and n ≥ 40 | Even as far as we can tell |
  | `unclear` | everything else (n 10–39 straddling 0.5, or posterior and record disagree) | Too early to tell |

- **Summary:** `counters` (unordered pairs), `pairs_n20` (unordered pairs with
  n ≥ 20), `consistent_share` = share of those whose raw 95% Wilson interval
  contains the strength expectation (how well "overall strength" explains
  matchups).
- Size: ~480 KB raw / ~52 KB gzipped for all 12 period × map blocks — the
  explorer page only. Profiles embed their own matchup rows.

  commander_stats) and `concentration`. When `verdict` is `one_player` or
  `few_players`, show the counts and the label, no percentage.
- `turn_order`: first_turn per_commander (mirror games included — the source
  cannot separate them). If either side has < 20 games, both sides'
  `wr`/`lo`/`hi` are null and `reportable` is false; otherwise the window's
  pilot gates apply to both sides.
- `maps`: per map, the same shape as `record` (that map's matchups /
  commander_stats / archetypes blocks).
- `tempo`: "how its games end", from turn_winrates buckets merged into < 8,
  8–10 and 11+ of the commander's own turns; `share` of its games and the
  field-wide `field_share`. If any bucket has < 30 games the all-time window is
  used instead (`fallback: true`, `source_window: "all"`). Mirror games are
  included (turn_winrates cannot separate them). The pilot gates of the
  source window apply to each bucket.
- `matchups`: played opponents from matchup_model (same period, map all),
  sorted by `est` (rows with `est: null`, i.e. n < 10, last, by n);
  `unplayed` lists opponents with no recorded games. Row fields and the
  `est`/`favored`/`evidence` rules are exactly matchup_model's pairs (from
  this commander's side: `favored: "a"` = this commander). `strength…` /
  `expected_vs_field…`: model inputs with 95% intervals, `null` below 20
  non-mirror games — don't headline them; the `record` is the headline.
  `best`/`worst`: up to 3 opponents (names; look them up in `opponents`) with
  **n ≥ 20 and `counter`/`lean` evidence**, i.e. the posterior interval
  excludes 50% and the raw record agrees; often empty in short windows.
- `ways_to_play`: archetypes.json rows (prefix "Macks: " stripped from
  `label`). `games` = decks (player-games) in the archetype. `record` only when
  `games ≥ 30` (`status: "established"`); otherwise `status: "emerging"` with
  no winrate. Every row has a `concentration`; an established archetype whose
  games are mostly one player's gets `record.verdict: "one_player"` and no
  winrate (about 40% of established archetype records today). Up to 6
  `key_cards` (distinctive by lift) and up to 3 example `decks` with deck
  names and usernames.
- `cards.signature`: up to 8 non-token cards with inclusion ≥ 25% (≥ 5 decks),
  ranked by `lift` = inclusion − `avg_inclusion_peers`. Peers are the
  commanders that can and do run the card's faction in that window (own
  faction, or ≥ 3 distinct cards of it in their decks; neutral cards: every
  commander), including this one; `peers` = how many. A peer that never runs
  the card counts as 0. `cards.core`: 10 most-included.
- `opening_hand`: commander_mulligan_stats cards seen ≥ 30 times: 5 highest and
  5 lowest keep rates (no card in both lists).
- If a file would exceed 80 KB the example decks, key cards and then the
  number of archetypes are trimmed (`trimmed: true` if it still does not fit).
  Current sizes: 40–57 KB.

### insights/community_decks.json — searchable deck library

```json
{
  "schema_version": 1, "as_of": "…", "count": 1895,
  "sort": "last_seen (1m, 3m, 6m, all) then games desc",
  "fields": { … },
  "chunks": null,
  "decks": [ { "deck_name": "JagrisBeasts", "username": "Zoe", "commander": "Jagris, the Huntsman",
               "commander_slug": "jagris-the-huntsman", "faction": "grenalia",
               "archetype": "Danrir, Omenhound / Call of the Jungle", "deck_code": "wpFK…",
               "games": 66, "games_30d": 3, "last_seen": "1m", "maps": ["Dunes", "Snowmelt", "Tropics"] } ]
}
```

- One row per (commander, `deck_code`), collected from every period × map
  `decklists` in archetypes.json. Deck codes decode with `site/js/deckcode.js`
  and link to `decks/<commander_slug>/?code=<deck_code>`.
- `games`: the largest per-window count for that exact list — a lower bound on
  its all-time games (archetypes.json only lists each archetype's top 20
  lists per window). `games_30d`: count in the 1m/all listing, `null` when not
  listed there. `last_seen`: narrowest period that lists it (recency proxy —
  the pipeline publishes no per-list dates). `maps`: map-specific listings
  that include it. `username`: the most common pilot of that list across
  listings.
- No per-list wins: the pipeline does not publish them (archetype records are
  in the profiles).
- If the index ever exceeds 1.5 MB it is split: `chunks` lists
  `community_decks/part-NNN.json` files (`{part, of, decks}`) and `decks` is
  empty. Today it is a single ~640 KB file (~110 KB gzipped).
